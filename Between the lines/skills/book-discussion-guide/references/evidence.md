# Evidence and persistence contract

The report schema defines the guide body. All object fields are required and extra fields forbidden; unknown publication year/metadata use null. Facts and interpretations live in the claims ledger. Every substantive content block references claimIds; each claim references sourceIds. Questions and hypothetical parallels cite the book evidence that motivates them. Never portray hypothetical parallels as factual claims.

Runtime validation additionally requires unique source/claim/quote IDs, resolvable references, factual author-fact references, quote/source consistency, HTTP(S) URLs, and at most 25 quoted words per canonical source URL. The app verifies source URLs against web-search tool provenance and quotes against the research packet. These checks establish traceability, not independent proof of truth or exact wording on the live webpage; the research model must inspect the page text. Metadata is copied unchanged from research into the report.

The app wraps the body with id, createdAt, input (title/author/grade/depth), model, responseIds, and provenanceUrls. Reports are immutable bundles: reports/<id>/report.json and report.md. index.json lists complete bundles and aliases; directory names are hashes, never user paths. Temporary directories are not published. The filesystem adapter serializes work through a directory lock and atomically renames bundles and the manifest; it builds library listings from validated bundles, recovering lookup after a crash between bundle and index commit. A later save or the repair-index script refreshes the manifest. An abandoned lock requires operator removal after confirming the old process has stopped.

Cache identity is title + author, not grade/depth. Title-only reuse is allowed only for a unique local title match, with the saved author visible. Verified aliases may match but fuzzy edit distance does not. If no author was provided and online research identifies multiple plausible books, return candidates rather than synthesize. Database/object-store adapters implement list/get/find/save/withLock with equivalent atomicity and distributed locking.
